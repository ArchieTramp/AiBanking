# ADR-0002: Выбор инструмента для миграций БД

## Статус
Принято.

## Контекст
Приложение использует PostgreSQL в качестве основной базы данных. Схема БД будет меняться по мере развития проекта (добавление новых таблиц, полей, индексов). Необходим инструмент, который позволяет версионировать изменения схемы, применять их и откатывать.

## Решение
Мы выбрали **Alembic**.

**Почему Alembic:**
1.  **Стандарт для SQLAlchemy**: Alembic разработан той же командой, что и SQLAlchemy, и является де-факто стандартом для миграций в проектах на SQLAlchemy.
2.  **Поддержка асинхронности**: Alembic имеет шаблон `async` (генерируется через `alembic init -t async`), который корректно работает с асинхронным движком SQLAlchemy (через `async_engine_from_config` и `run_sync`). Это критично, так как наше приложение полностью асинхронное.
3.  **Автогенерация миграций**: Команда `alembic revision --autogenerate` сравнивает модели (metadata) с текущим состоянием БД и автоматически создает файл миграции. Это экономит время и снижает риск ошибок.
4.  **Гибкость**: Мы можем вручную добавлять SQL-код в миграции (например, для включения расширения `pgvector` через `op.execute("CREATE EXTENSION IF NOT EXISTS vector")`).

## Последствия
*   **Плюсы**: Полная интеграция с SQLAlchemy, поддержка async, автогенерация, контроль версий схемы в Git.
*   **Минусы**: Требует настройки `env.py` (импорт моделей, настройка URL), а также дисциплины: перед применением миграции нужно проверять сгенерированный код.
