# ADR-0001: Выбор технологического стека

## Статус
Принято.

## Контекст
В рамках домашнего задания необходимо реализовать сервис для расчета графиков кредитов. Требуется высокая производительность, асинхронность (работа с БД и внешними сервисами), удобство разработки и воспроизводимость окружения.

## Решение
Мы выбрали следующий стек:
1.  **Python 3.12 + FastAPI**: FastAPI обеспечивает высокую скорость работы (на уровне Starlette), автоматическую генерацию OpenAPI-документации (Swagger UI) и нативную поддержку асинхронности, что критично для работы с БД.
2.  **uv (вместо pip/poetry)**: `uv` — это современный, сверхбыстрый менеджер пакетов и окружений на Rust. Он обеспечивает воспроизводимость сборки (благодаря `uv.lock`) и значительно ускоряет установку зависимостей.
3.  **SQLAlchemy 2.0 (async) + asyncpg**: SQLAlchemy 2.0 предоставляет мощный ORM и Core с поддержкой асинхронного I/O. `asyncpg` — самый быстрый асинхронный драйвер для PostgreSQL, который отлично работает в связке с SQLAlchemy.
4.  **PostgreSQL + pgvector**: PostgreSQL выбран как надежная реляционная СУБД. Расширение `pgvector` необходимо для хранения векторных представлений (эмбеддингов), что может понадобиться в будущем (например, для поиска похожих кредитных предложений).
5.  **Docker Compose**: Позволяет поднять всю инфраструктуру (БД, Temporal, само приложение) одной командой, обеспечивая изоляцию и воспроизводимость среды на любой машине.
6.  **Temporal**: Используется для оркестрации долгоживущих бизнес-процессов (например, обработка заявок на кредит, фоновые задачи).

## Последствия
*   **Плюсы**: Высокая производительность, асинхронность, удобная документация, быстрая установка зависимостей, воспроизводимость среды.
*   **Минусы**: Стек сложнее для новичков (асинхронность, Docker, Temporal), чем классический синхронный монолит на Django/Flask.
